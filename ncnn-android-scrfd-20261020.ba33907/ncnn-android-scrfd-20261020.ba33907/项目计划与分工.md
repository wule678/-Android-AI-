# 《操作系统》综合实验 · 项目计划与分工

> 课程：操作系统（2024 级人工智能 1/2/3 班）
> 项目：《基于 Android 平台的轻量化 AI 模型部署与优化 —— 前置摄像头人脸检测、识别和活体检测》
> 周期：8 周　｜　组队：2 人
> 交付：可安装 APK + 完整源工程 + README + Git 仓库 + PPT（15–20 页）+ 现场演示答辩

## 1. 项目目标（一句话）

在 8 周内开发一款**可安装、可离线运行**的 Android App，使用**前置摄像头**实时采集画面，完成
**人脸检测、人脸识别、活体检测**三项由**真实端侧深度学习模型**完成的功能，并在 App 中真实落地
操作系统核心机制（进程/线程/IPC/信号量/I/O 事件），最后完成对照实验、优化与答辩。

> 红线：三项 AI 功能必须由部署在设备上的真实模型完成，不能只靠传统图像处理或调用云端接口替代。
> 红线：必须在 Android **真机**上验收，模拟器不能替代最终真机。

## 7. 决策点与风险

1. **推理框架**：作业推荐 "ONNX Runtime Mobile / LiteRT(TFLite) 等"。当前 ncnn 属于"等"里的移动端推理框架，**建议保留 ncnn 并三模型统一用 ncnn**，避免重复换框架；若老师严格卡 ONNX Runtime，需尽早确认并评估迁移成本。
2. **语言**：作业推荐 Kotlin，当前工程是 **Java**。Java 也能完成 AIDL/Service/Semaphore；若想拿"推荐语言"分，可把 B 负责的 UI/Service 层逐步 Kotlin 化，JNI 仍用 C++。
3. **模型许可**：EdgeFace、MiniFASNetV2 模型文件能否随工程再分发要看各自 license，README 需写清来源与获取/转换方式。
4. **真机依赖**：Camera2/HAL3 在很老设备上可能崩溃；性能数据必须以最终真机为准，模拟器不能替代。
5. **数据合规**：人脸数据采集需经本人同意，仅用于教学，报告注明样本有限、结论仅适用于教学数据集。

## 9. 实验数据采集步骤

### 9.0 采集工具准备

- 画面实时指标：FPS（右上角）、`det/wait/recog/live`（各阶段耗时）、`queue/dropped/done`（队列状态）
- CPU 占用：`adb shell dumpsys cpuinfo | grep scrfdncnn`
- 内存：`adb shell dumpsys meminfo com.tencent.scrfdncnn`
- 屏幕录制：`adb shell screenrecord /sdcard/demo.mp4`
- 截图：`adb exec-out screencap -p > shot.png`
- 每次实验固定条件（同机型/系统版本/光照/距离/模型 500m_kps/CPU 后端），记录样本数、均值、P50/P95

### 9.1 实验一：系统运行基线（无需改代码）

1. 装 APK 后启动，对准人脸，等 FPS 稳定（约 10 秒）
2. 连续观察 30 秒，每隔 5 秒记录一次：FPS、det、wait、recog、live、dropped、done
3. 用 `dumpsys cpuinfo` 记录 CPU 占用（本进程 + 推理进程）
4. 重复 3 次取均值 → 得到**性能基线**

### 9.2 实验二：线程数 1/2/4 对比（改代码）

1. 改 `app/src/main/jni/edgeface.cpp`、`minifasnet.cpp`、`scrfd.cpp` 里 `net.opt.num_threads = ncnn::get_big_cpu_count();` 为固定值 `1`（再改 `2`、`4`）
2. 每改一次 → 重新构建 + 安装 → 按 9.1 步骤测一遍
3. 记录表格：`线程数 | FPS | det | recog | live | CPU`
4. 结论：线程数对端到端延迟/CPU 的影响（找出最优线程数）

### 9.3 实验三：队列深度对比（Semaphore，改代码）

1. 改 `app/src/main/jni/scrfdncnn.cpp` 里 `static const int g_max_queue = 3;` 为 `1`、`5`
2. 观察丢帧率（`dropped/(dropped+done)`）和 `wait`（队列等待耗时）
3. 记录表格：`队列深度 | 丢帧率 | wait | FPS`
4. 结论：有界队列深度对"背压 vs 延迟"的权衡（越小越能限流但越易丢帧）

### 9.4 实验四：模型精度测试（无需改代码）

- **活体**：真人、打印照片、屏幕翻拍各测 20 次，记录判对/判错 → 算 TPR/FPR，保留误判样例截图
- **识别**：注册 3~5 人，每人各识别 10 次，记录识别准确率、误拒率（未注册人脸判为"未知"的比例）、阈值说明

### 9.5 实验五：单进程 vs 双进程对比（需先打通 AIDL 数据流）

1. 单进程模式：当前状态（消费者线程在主进程）
2. 双进程模式：把识别/活体改成走 `InferenceService`（AIDL 传图 → Service 推理 → 回传结果）
3. 记录：端到端延迟、内存、进程数、服务崩溃后断连/超时/重连恢复时间
4. 结论：双进程隔离带来的稳定性和额外开销

### 9.6 实验六：模型优化对比（fp16 vs fp32，改转换）

1. 用 `pnnx xxx.pt inputshape=[...] fp16=0` 重新导出 fp32 模型（MiniFASNetV2 / MobileFaceNet）
2. 替换 assets 后重新构建，对比：精度、模型体积、推理耗时
3. 记录表格：`模型 | 精度(FP16) | 体积(FP16) | 耗时(FP16) | 精度(FP32) | 体积(FP32) | 耗时(FP32)`

### 9.7 数据整理

- 所有实验都保存**原始数据**（截图/录屏/logcat），报告里用表格 + 折线图呈现
- 标注样本有限、结论仅适用于教学数据集
